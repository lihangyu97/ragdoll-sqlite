# ragdoll-sqlite 规划（Roadmap 设计记录）

> 已确认的功能设计记录。状态：`已确认`=设计定稿待实现；`已实现`=已完成。

## 1. 刷新当前表（已确认，待实现）

**位置**：表头行右侧——`表名 ｜ 类型Tag ｜ 共 N 行 [刷新]`，`RefreshOutlined` 图标按钮 + Tooltip「刷新当前表」。

**语义**：刷新当前表的**行数据 + 结构信息**（不依赖当前 tab，数据/结构都刷新）。

**实现要点**：

- 前端：`useTableData` 暴露 `refresh()`，重新拉取 rows + info（沿用序号守卫，防过期响应覆盖）
- 服务端：⚠️ **必须顺带清行数缓存**——`SqliteDb` 的 `rowCountCache` 是进程内缓存，外部改库后只刷新前端会拿到旧 total。
  方案：`POST /api/refresh` 清空缓存（或 rows 请求带 `forceCount=1` 跳过缓存）
- 可选：同时重新拉取 `/api/tables`（表结构可能被外部 ALTER）

## 2. 按列查询/过滤（已实现 ✅）

> 实现：`FilterModal`（按结构生成表单）+ `FilterBar`（条件标签）+ rows 接口 `filter` 参数
> （服务端列名白名单 + 值参数化，过滤态不走行数缓存）。

**交互形态**：

```
表名 ｜ 类型Tag ｜ 共 N 行  [刷新] [查询]
[已过滤: age ≥ 18 ×  name 包含 "张" ×]   ← 过滤条件标签，可单独移除 / 一键清除
┌─────────────────────────────────────┐
│  #  id   name   age  ...            │  ← 过滤后的数据（分页/悬停/行详情全部复用）
└─────────────────────────────────────┘
```

**决策过程**（备选方案一：数据/结构之间加查询 Tab + 结果弹窗，已否决）：

- Tab 语义是"同一实体的不同视角"；查询是**动作**，应放工具条而非 Tab
- 结果弹窗需要重造分页/排序/行详情，而就地过滤直接复用数据表全部能力
- 过滤状态通过标签可见、可清除，避免"查询态"与"浏览态"混淆

**表单设计（按表结构生成）**：

- TEXT → 输入框 + 运算符（`=` / `≠` / `包含 LIKE` / `为空` / `不为空`）
- INTEGER / REAL → 数值范围（`≥` / `≤` / `=`）
- 时间字段 → 可选范围；BLOB → 不参与过滤
- 只把**填了值**的字段拼进 WHERE

**服务端实现**：

- 扩展 `GET /api/tables/:name/rows`：新增过滤参数（列名 + 运算符 + 值）
- 列名走 **schema 白名单**校验（沿用 requireTable/quoteIdent 模型）；值全部**参数化**
- 分页 / count 逻辑不变；过滤后 total 用过滤后的 count（注意行数缓存需区分过滤态）

**与 SQL 控制台的关系**：本功能是"有结构的按列过滤"；「查询」菜单里的 SQL 编辑器是自由查询，二者并存。

## 其他已讨论、未定稿的规划

- **顶部历史页签栏**：打开过的表/视图做成可切换、可关闭的页签（antd `Tabs editable-card`），纯 state 实现，不需要 router
- **URL 直达**：`?view=&table=&tab=` 参数同步（读 + `replaceState`），不引入 router；若需跨重启可书签，配套"固定端口 + 稳定 token（按 db 路径派生）"
- **SQL 查询控制台**：「查询」菜单占位页，后续接编辑器 + 服务端只读 SELECT 接口（沿用防注入模型）
- **主页图表**：「主页」菜单占位页，后续接图表
